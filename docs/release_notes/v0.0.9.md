# Release 0.0.9

## Overview

Battery display stability release + UDP transfer reliability (selective-repeat
bitmap NACK, paced retransmit) + CI infrastructure + Apache-2.0 license.

## Changes

### Battery display smoothing (directional rate-limit)

- The displayed SoC now moves **directionally** toward the fuel-gauge value:
  while charging it only increases (catch up + track charge); while discharging
  it only decreases (track depletion). A normal charge/discharge rate (≤3%/poll)
  tracks with **zero lag**; only the gauge's large one-shot voltage reconciliation
  (~5-15% on the first reboot after cycling) is held during discharge and
  corrected on the next charge.
- The displayed value is **persisted across reboot** (new `displayed_soc` field
  in the fuel-gauge state record, format version 2) so it resumes from the
  pre-reboot reading — no cross-reboot lag accumulation.
- Configurable via `CONFIG_CLIP_BATTERY_DISPLAY_MAX_STEP` (default 3%/poll; 0 =
  raw gauge, no smoothing).

### Battery state persistence on hard power-off

- A 7-second long-press triggers a PMIC **hardware reset** that bypasses the
  software graceful shutdown (where the fuel-gauge state is normally saved).
- The device now **saves the fuel-gauge state at the 3-second power-off level**
  (POWER_OFF_SHOW), deferred to the system workqueue so it cannot block the
  power-off flow. The hard reset no longer loses the SoC.
- `battery_save_fg_state()` is now **mutex-safe** (locks `battery_mutex`
  internally), eliminating a race between `nrf_fuel_gauge_state_get()` and
  `nrf_fuel_gauge_process()` on different threads.

### UDP selective-repeat (bitmap NACK)

- `FILE_ACK` extended: a NACK may now carry a **missing-seq bitmap**
  (`[0x03][0x01][total_seqs:2 LE][bitmap]`, bit i set = seq i missing). The
  device retransmits **only the missing frames** by seq (via the
  `repair_missing` transport op), then re-sends FILE_END. Converges even when
  each round loses a different subset of frames.
- Backward compatible: a legacy 2-byte NACK (or an old device ignoring the
  bitmap) falls back to whole-file retransmit.
- File CRC now covers the **full file** regardless of `sendto()` success (was:
  a sendto failure left a permanent hole → unmatchable CRC).

### UDP retransmit pacing + backoff

- Whole-file retransmit now **paces each chunk** (`CLIP_UDP_REPAIR_PACE_US`,
  default 1ms/chunk) — the link just dropped frames, so re-blasting at full
  speed risks losing them again.
- NACK round backoff shortened from 50ms×retry to `CLIP_UDP_NACK_BACKOFF_MS`
  (default 10ms×retry). Both Kconfig-tunable.

### UDP heartbeat log removed

- The per-heartbeat `LOG_DBG` was removed — the companion app now sends a 200ms
  heartbeat during transfer to keep the phone's WiFi out of power-save, and
  logging every one would spam. The firmware safely ignores 0x30 during
  transfer (sets `client_active`, no state-machine interference).

### BLE pair overwrite (debug only)

- `CONFIG_BT_KEYS_OVERWRITE_OLDEST=y` in prj.conf (debug): a new phone may pair
  and overwrite the single stored bond without first clearing it — convenient
  for testing. Production snippet sets `=n` so the device stays locked to its
  owner until an explicit `AT+PAIR=reset`.

### CI + license

- `.github/workflows/firmware.yml`: push/PR compilation check (NCS v3.3.0 +
  MCUboot patches + west build).
- `.github/workflows/mobile-ci.yml` (fast, PR) + `mobile-verify.yml` (full,
  push/manual): Flutter analyze+test, Android unit tests, iOS swift build.
  Moved from `mobile/.github/workflows/` (GitHub only runs root workflows).
- `LICENSE`: Apache-2.0 at the repo root (matches firmware SPDX headers).
- `README.md`: Mobile App & SDK section + clarified licensing.

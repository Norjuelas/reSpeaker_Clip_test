# Release 0.0.6

## Overview

**Charging reliability + pairing/recovery robustness + protocol accuracy release.**
Adds a charging-recovery watchdog that restarts charging after an NPM1300
safety-timer abort (including an idle-kickstart that recovers a deeply
discharged *protected* cell), a full charge now reads 100%, the AT+PAIR=reset
and MCUboot recovery erase actually clear the bonds, serial recovery exits 3 min
after USB is unplugged (battery-drain guard), and the BLE AT protocol spec is
corrected end-to-end to match the real JSON responses.

Two firmware variants are published per release: **debug** (UART console on, SD
log on at INF) and **production** (console off, ~170µA idle).

## Changes

### Battery & Charging

- **Charging-recovery watchdog**: when VBUS is present and the charger latches a
  safety-timer abort (trickle/charge timeout — `BCHGERRREASON`), the charger is
  released and re-enabled (Nordic's `TASKRELEASEERR` + `BCHGENABLESET` path).
  Triggered immediately on the PMIC `CHG_ERROR` event (2s) plus the 60s poll,
  rate-limited to 30s; only auto-recovers the safety-timer aborts.
- **Idle kickstart for protected cells**: a deeply discharged cell that has
  tripped its own undervoltage protection can defeat the recovery above — after
  the error is cleared the NPM1300 may refuse to re-enter trickle (the cell still
  looks open/high-Z), leaving the charger idle with no error latched. A second
  path now re-enables charging whenever VBUS is in, the charger is idle, and the
  cell is below ~2.4V. This is what lets a protected cell recover that the fixed
  10-minute trickle could not.
- **Trickle exit threshold lowered 2.9V → 2.5V** so a deep cell recovers in fewer
  cycles.
- **Charge termination raised 4.20V → 4.25V** so the fuel gauge reaches ~100%
  instead of settling at ~99%.
- **Displayed % now equals actual SoC** — the bottom reserve that capped the
  reading at 97% is removed. **Charge complete pins the display at 100%** (the
  fuel-gauge model plateaus at ~99% even after the charger reports COMPLETE) and
  bypasses SoC smoothing so it shows immediately.
- **Low-battery auto-shutdown removed** (unreliable SoC during PMIC I2C failures
  caused false shutdowns); low battery shows a UI warning only.

### Settings Robustness

- **Settings-load watchdog**: `settings_load` cannot be interrupted, so a corrupt
  settings file (typically from repeated BLE pair/unpair) blocked boot for ~40s
  and boot-looped. A watchdog on a separate thread wipes the file and reboots if
  the load hasn't returned in 1s; a normal (<100ms) load cancels it.

### Pairing & Recovery

- **AT+PAIR=reset now actually clears the bonds**: it calls `ble_clear_bonds()`
  + `settings_save()` (persisting the deletion) and formats the SD card (privacy
  wipe) before rebooting. Previously it formatted the SD but never persisted the
  bond clear, so the device came back still-bonded and could not pair.
- **MCUboot recovery erase-settings reliably clears bonds**: the erase is widened
  to the first two LittleFS blocks (128KB) — the superblock metadata pair is
  pinned at blocks {0,1} and, with the 64KB block size, spans 128KB, so a single
  64KB erase left block 1 to recover the superblock. NPM1300 LDO2 + external
  flash power are now enabled at MCUboot init (`regulator-boot-on`) so the erase
  actually reaches the chips.
- **Serial recovery exits 3 min after USB unplug** (new MCUboot patch 0006): a
  forgotten recovery session on battery no longer drains the cell. While USB is
  present recovery never exits (active DFU / rescuing a broken app is never
  interrupted); 3 min of no VBUS cold-reboots to the app.

### Protocol / Docs

- **BLE AT protocol spec corrected end-to-end** (`docs/protocol.md`): every
  response example now matches the actual JSON (`{"ok":..,"data":..,"msg":..}`).
  Errors use `"msg"` (not `"error"`); the fictional numeric error-code catalog is
  removed (the code never emits codes); per-command response shapes, invented
  fields, and missing `data` wrappers are fixed; `AT+DFU` and `AT+WIFICFG` are
  documented; notifications corrected to the real ble/usb/storage events.
- **Removed `AT+PURGE` / `AT+PURGEABLE`** (unused; PURGEABLE's JSON used `%llu`,
  unsupported by newlib-nano).
- Fixed the remaining `%llu`/`%lld` log sites with `%u` casts.

### Logging

- Application-wide log cleanup (terse strings, noisy logs demoted INF→DBG) freed
  ~6KB of flash.

## Upgrading

### 1. USB Serial DFU (recovery mode, no programmer needed)

Hold the **user button** while connecting USB to enter MCUboot serial recovery:

```sh
mcumgr image upload clip-0.0.6-production-signed.bin \
    --conntype serial --connstring /dev/ttyACM0
```

(or the `-ota.zip` for app + net core). Reset; MCUboot verifies the signature
and swaps on the next boot. Recovery exits automatically 3 min after USB is
unplugged.

### 2. Programmer (J-Link / west)

```sh
west flash --build-dir build-clip && nrfutil device reset
```

## Build Environment

- NCS v3.3.0 (Zephyr RTOS), board `clip/nrf5340/cpuapp`
- `export ZEPHYR_EXTRA_MODULES=$(pwd)` before building (sysbuild: mcuboot + app + ipc_radio)
- 6 MCUboot patches applied by `scripts/build_release.sh`

## Known Issues

- Debug build idle current is higher than production due to the UART console leak
  (~570µA) — by design; use the production image for battery testing.
- The 4.25V charge termination is a mild overcharge of the 4.20V-rated cell;
  accepted to reach 100% at the cost of some cycle life.

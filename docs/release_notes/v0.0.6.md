# Release 0.0.6

## Overview

**Pairing/recovery robustness + battery display accuracy + protocol correctness
release.** Fixes the AT+PAIR=reset and MCUboot recovery erase so they actually
clear the BLE bonds, makes a full cell read 100%, removes the unreliable
low-battery auto-shutdown, adds a settings-load watchdog to break the corrupt-
file boot loop, and corrects the BLE AT protocol spec end-to-end to match the
real JSON responses.

Two firmware variants are published per release: **debug** (UART console on, SD
log on at INF) and **production** (console off, ~170µA idle).

## Changes

### Battery & Charging

- **Charge termination raised 4.20V → 4.25V** so the fuel gauge reaches ~100%
  instead of settling at ~99% (the cell rests ~4.18V after CV termination at
  ITERM). The cell is a 4.20V-rated Li-Po, so 4.25V is a mild overcharge
  accepted to hit full; cycle-life tradeoff.
- **Displayed % now equals actual SoC** — the bottom reserve that capped the
  reading at 97% is removed (it existed only to buffer graceful low-battery
  shutdown, which was removed). A full cell now reads **100%**.
- **Charge-complete pins 100%**: when the NPM1300 reports COMPLETE, the display
  is forced to 100% and SoC smoothing is bypassed (the fuel-gauge model
  plateaus at ~99% even after termination).
- **Low-battery auto-shutdown removed** — it was unreliable (PMIC I2C read
  failures made SoC wrong, causing false shutdowns / boot loops). Low battery
  shows a UI warning only; power-off is manual (`AT+POWEROFF` / button).
- **Deep-discharge recovery**: `vbatlow-charge-enable` lets the charger activate
  even when the cell is below the VBATLOW threshold (~2.4V, e.g. after the
  protection IC trips), so a deeply discharged *protected* cell can recover via
  the NPM1300's built-in trickle (10% ICHG). No software watchdog needed.

### Settings-Load Watchdog

- `settings_load` cannot be interrupted, so a corrupt settings file (typically
  from repeated BLE pair/unpair churning bond records) made it block for ~40s
  and boot-loop. A watchdog on a separate thread (the system workqueue — runs
  independently of the main thread where `settings_load` executes) arms before
  the load: if it hasn't returned in `CLIP_SETTINGS_LOAD_TIMEOUT_MS` (3s), the
  file is unlinked and the chip reboots — the next boot loads clean defaults in
  <100ms. Guards both the `config` subtree load and the `bt` bond-key load.

### Pairing & Recovery

- **AT+PAIR=reset now actually clears the bonds**: it calls `ble_clear_bonds()`
  + `settings_save()` (persisting the deletion) and formats the SD card (privacy
  wipe) before rebooting. Previously it formatted the SD but never persisted the
  bond clear, so the device came back still-bonded and could not pair.
- **MCUboot recovery erase-settings reliably clears bonds**: the erase is
  widened to the first two LittleFS blocks (128KB) — the superblock metadata
  pair is pinned at blocks {0,1} and, with the 64KB block size, spans 128KB, so
  a single 64KB erase left block 1 to recover the superblock. NPM1300 LDO2
  (SD power) is now controlled on-demand by the erase-SD command
  (`regulator_enable` → erase → `regulator_disable`), NOT via `regulator-boot-on`
  — a leaked boot-on reference would prevent the app's SD idle-power-gating from
  ever turning LDO2 off (the NPM1300 regulator init seeds the app's refcount
  from the physical PMIC register via `get_enabled()`). External flash power
  (`flash_vdd`) is enabled in the overlay.

### AT Commands / Logging

- **Removed `AT+PURGE` / `AT+PURGEABLE`** (unused; PURGEABLE's JSON used `%llu`,
  unsupported by newlib-nano).
- Fixed the remaining `%llu`/`%lld` log sites with `%u` casts.
- Added `<zephyr/settings/settings.h>` to at_commands.c for the PAIR reset.

### Protocol / Docs

- **BLE AT protocol spec corrected end-to-end** (`docs/protocol.md`): every
  response example now matches the actual JSON
  (`{"ok":..,"data":..,"msg":..}`). Errors use `"msg"` (not `"error"`); the
  fictional numeric error-code catalog is removed (the code never emits codes);
  per-command response shapes, invented fields, and missing `data` wrappers are
  fixed; `AT+DFU` and `AT+WIFICFG` are documented; notifications corrected to
  the real ble/usb/storage events.
- `requirements.md`, `development.md`: PURGE references removed.
- `architecture.md`: Battery section updated (no low-battery shutdown, 100%
  display, vbatlow recovery). Settings-watchdog added to CLAUDE.md pitfalls.
- `patches/mcuboot/README.md`: patch 0004 updated (128KB erase, on-demand LDO2,
  refcount-leak explanation).

### Configuration (Kconfig)

- `CLIP_SD_IDLE_DELAY_MS` (45000) — SD card idle power-off delay.
- `CLIP_ADV_FAST_TIMEOUT_MS` (30000) — BLE fast advertising timeout.
- `CLIP_SETTINGS_LOAD_TIMEOUT_MS` (3000) — settings-load watchdog timeout.

## Upgrading

### 1. USB Serial DFU (recovery mode, no programmer needed)

Hold the **user button** while connecting USB to enter MCUboot serial recovery:

```sh
mcumgr image upload clip-0.0.6-production-signed.bin \
    --conntype serial --connstring /dev/ttyACM0
```

(or the `-ota.zip` for app + net core). Reset; MCUboot verifies the signature
and swaps on the next boot.

### 2. Programmer (J-Link / west)

```sh
west flash --build-dir build-clip && nrfutil device reset
```

## Build Environment

- NCS v3.3.0 (Zephyr RTOS), board `clip/nrf5340/cpuapp`
- `export ZEPHYR_EXTRA_MODULES=$(pwd)` before building (sysbuild: mcuboot + app + ipc_radio)
- 5 MCUboot patches applied by `scripts/build_release.sh`

## Known Issues

- Debug build idle current is higher than production due to the UART console leak
  (~570µA) — by design; use the production image for battery testing.
- The 4.25V charge termination is a mild overcharge of the 4.20V-rated cell;
  accepted to reach 100% at the cost of some cycle life.

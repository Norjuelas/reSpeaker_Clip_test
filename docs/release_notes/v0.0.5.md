# Release 0.0.5

## Overview

**Idle power optimization release.** Steady-state idle current is reduced from
~1.5mA to **~170µA** (production image), measured on the 3V3 rail, while keeping
BLE connectable, WiFi, SD recording, and USB fully functional. This release also
adds a debug/production firmware split, SD-log control, and a broad set of BLE /
storage / transfer reliability fixes.

Two firmware variants are published per release: **debug** (UART console on, SD
log on at INF) and **production** (console off, ~170µA idle).

## Changes

### Power Management (the focus of this release)

Idle power budget (3V3 rail), each item measured in isolation before stacking:

- **nRF5340 DCDC regulators** (`vregmain` / `vregradio` = `NRF5X_REG_MODE_DCDC`):
  the board DTS previously left the internal regulators in LDO mode — switching to
  DCDC saves ~500–600µA.
- **SD card idle power-gating**: after 45s of no record / transfer / AT / USB /
  log activity, the SD stack is torn down — unmount → disk deinit → SPI4
  runtime-PM suspend → CS parked low → LDO2 off. The next access lazily remounts
  via `storage_ensure_mounted()`. Safe: filesystem is flushed (unmount) before
  power is removed, and active recording/transfer is never interrupted.
- **SPI bias-pull-up removed** from `spi3` / `spi4` (SPI is push-pull and needs no
  pull-up) with `bias-pull-down` added to `spi4_sleep`; ~750µA recovered.
- **UART console leak**: the debug console keeps the UARTE peripheral enabled at
  idle (~570µA, baud-independent). The production snippet disables the console +
  UART log backend. (Debug builds keep the console for development.)

Result: **production idle ~170µA**; debug build idles higher (console on).

### Debug / Production Firmware Split

- Default build (no snippet) = **debug**: UART console on, FS log to `/SD:/LOG`
  at INF level (`CONFIG_CLIP_LOG_FS_DEFAULT_ON` follows `LOG_BACKEND_UART`).
- `production` snippet = **production**: console + UART log backend off, FS log
  off. Build with
  `-- -DSNIPPET_ROOT=$(pwd)/applications/clip -DSNIPPET=production`.
- Note: the snippet does not override app-only `CLIP_*` Kconfig symbols directly
  (a snippet's conf is broadcast to every sysbuild image, including mcuboot, where
  they are undefined). The FS-log default is instead coupled to `LOG_BACKEND_UART`.

### New AT Command

- `AT+LOG=off|info|debug` — toggle the SD log backend at runtime. `off` lets the SD
  card idle power-gate; `info`/`debug` force it to stay mounted at INF/DBG.

### BLE Reliability

- Fixed the slow-advertising interval (was a copy-paste of the fast 30–60ms
  interval; now genuinely slow). Un-bonded devices now also drop to slow
  advertising after the fast window.
- Connection parameters tightened (interval 15–30, supervision timeout 800); param
  requests are accepted (clamped) rather than rejected.
- CCC notify handlers use a mask (`& BT_GATT_CCC_NOTIFY`) instead of equality, so
  notifications are not dropped when additional CCC bits are set.

### Storage & Transfer Robustness

- **Storage-full handling**: percentage-based via `fs_statvfs`
  (`CONFIG_CLIP_STORAGE_FULL_PERCENT`, default 95%). Recording is refused with an
  on-screen "Storage Full" error and a BLE event when the SD is full.
- **Transfer cancel** is now thread-safe and marks the transfer ERROR
  synchronously, so re-download works correctly after a BLE drop.
- `AT+NAME` capacity raised 32B → **256B**; surrounding quotes stripped from the
  argument.
- `disk_access_init` now tolerates `-ENOTSUP` (already-initialized after an MSC
  release); USB SD removal uses `storage_ensure_mounted()` instead of a forced
  remount.

### Battery

- Reserve capacity and early low-battery shutdown tuning; SoC smoothing is
  bypassed below reserve so a genuine low reading is acted on immediately rather
  than averaged away.

### Python Client (`tests/clip`)

- AT commands now retry on BLE-notify drops (`_send_and_check`, retries=2 default).
- Robust JSON parsing around brace-matched notifications.

## Bug Fixes

- Fixed FS log backend not reflecting runtime `AT+LOG` changes (re-activation path).
- Fixed `AT+NAME="value"` argument quoting causing a JSON parse error.
- Fixed production build abort: snippet no longer broadcasts an undefined app
  symbol into the mcuboot image.

## Upgrading

Three paths, in order of convenience:

### 1. USB Serial DFU (recovery mode, no programmer needed)

MCUboot exposes a CDC-ACM serial recovery console over USB. This is the easiest
field upgrade — only a USB cable and `mcumgr` are required.

1. Install mcumgr (`go install github.com/apache/mynewt-mcumgr/cli/mcumgr@latest`).
2. Hold the **user button** while connecting USB (VBUS must be present) — the
   device enters serial recovery and appears as a USB serial port (e.g.
   `/dev/ttyACM0`).
3. Upload the app image:
   ```sh
   mcumgr image upload clip-0.0.5-production-signed.bin \
       --conntype serial --connstring /dev/ttyACM0
   ```
   (or the `.ota.zip` for a full app + net-core upgrade).
4. Reset; MCUboot verifies the signature and swaps on the next boot.

### 2. BLE OTA (nRF Connect / mcumgr)

Use the `.ota.zip` with the nRF Connect Device Manager app, or
`mcumgr image upload clip-0.0.5-*-ota.zip --conntype ble ...`.

### 3. Programmer (J-Link / west)

Flash the `merged.hex` (full image) when a programmer is available:
```sh
west flash --build-dir build-clip && nrfutil device reset
```

> The app's UART console (debug builds) and the bootloader's USB serial recovery
> are independent — production builds (console off) still support USB serial DFU.

## Build Environment

- NCS v3.3.0 (Zephyr RTOS)
- Board: `clip/nrf5340/cpuapp`
- `export ZEPHYR_EXTRA_MODULES=$(pwd)` before building (sysbuild: mcuboot + app + ipc_radio)

## Known Issues

- Debug build idle current is higher than production due to the UART console leak
  (~570µA) — by design; use the production image for battery testing.
- WiFi initialization may still fail on boards with QSPI signal-integrity issues
  (hardware, unchanged from 0.0.4).

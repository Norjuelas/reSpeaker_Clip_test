# Release 0.0.7

## Overview

**Bug-fix + reliability + crystal tuning release.** Adds BLE identity rotation
to fix the iOS stale-bond pairing failure, tunes the HFXO/LFXO internal load
capacitors, fixes a critical stack overflow in the settings loader, resolves
the jumping battery percentage, hardens WiFi AP re-enable, and cleans up audio
AGC/session handling. Product name unified to **reSpeaker** (lowercase `r`).

Two firmware variants are published per release: **debug** (UART console on,
SD log on at INF) and **production** (console off, ~170µA idle).

## Changes

### BLE — iOS stale-bond fix (identity rotation)

- **AT+PAIR=reset now rotates the BLE identity address** so iOS (which caches
  bonds with no API to remove them) sees a brand-new device and re-pairs
  fresh, without the user having to "Forget This Device" in Settings. The
  device name stays "Clip XXXX" (iOS keys bonds to address, not name). The
  rotated address persists across reboots via settings.
- `CONFIG_BT_ID_MAX=2` (allows a second local identity).
- `ble_active_id` derived at boot from `bt_id_get()` count; all advertising,
  bonding, and unpair operations use the active identity.

### Crystal Load-Capacitor Tuning

- The board has no external load capacitors for HFXO (32 MHz) or LFXO
  (32.768 kHz); the internal ones are now enabled with values tuned via the
  `tests/clip` `hfxo`/`lfxo` shell:
  - HFXO: `XOSC32MCAPS.CAPVALUE = 60` (raw; the nRF53 HFXO DTS binding only
    accepts femtofarad derived from per-chip FICR, so it is written directly
    from a `POST_KERNEL` `SYS_INIT`).
  - LFXO: `XOSC32KI.INTCAP = 1` (6 pF internal).

### Battery & Charging

- **Smoother SoC display**: EMA alpha 0.3 → 0.15, per-poll delta cap 3% → 1%,
  so the displayed percentage no longer jumps around.
- **Sticky 100% on unplug**: once charging reports complete, the display
  holds 100% even after VBUS is removed, until the real SoC drops below 96%.
  Fixes the "full charge, unplug, immediately drops to 99%" behavior.
- **read_and_update() thread race fixed**: the function was called from both
  the display thread and the system workqueue without serialization; the
  nRF Fuel Gauge is non-reentrant, so concurrent calls corrupted the SoC
  integration (root cause of the jumping percentage). Now serialized with a
  mutex.
- **init_complete gate enforced**: the `init_complete` flag was written but
  never read — the PMIC event callback could call `clip_post_event`
  (`k_sem_give` on an uninitialized semaphore) during the boot window before
  `clip_event_init`. Now guarded with `if (!init_complete) return;`.

### WiFi

- **wifi_off now waits for AP_DISABLE_RESULT** (3 s timeout) before
  `net_if_down`, preventing a race where a fast `wifi_on` (auto-off timer →
  user command) fails on a half-disabled radio.
- `wifi_start_dhcp_server` return value is now checked (was silently ignored).

### Audio

- **AGC / high-pass-filter state reset between recordings**: `hp_x1`,
  `agc_envelope`, `agc_gain_q8` were function-statics that persisted across
  recordings; a loud recording left stale AGC gain, attenuating the first
  ~5 s of the next recording. Moved to file scope and reset on each
  `audio_start_recording_internal`.
- **Recording start failure no longer leaks storage**: `storage_create_session`
  / `storage_create_file` were called before the fallible mic/Opus/DMIC init
  steps; a failure left an orphan session (empty 0001.opus + session.json
  visible in AT+LIST). Storage creation moved to after DMIC trigger succeeds.
- **recording_time_ms 32-bit overflow fixed**: `uint32_t * int` wrapped at
  ~49.7 days; cast to `(uint64_t)` before the multiply.

### Critical Fix: config_settings_set Stack Overflow

- `config_settings_set()` read `entry->size` (up to 257 bytes for
  `device_name`) into a 32-byte stack buffer → 225-byte stack overflow on
  every `settings_load` after a `config_save`. Fixed by reading directly
  into the config struct field, removing the intermediate buffer.

### Removed: Dead UDP Heartbeat Code

- `send_heartbeat()` + `heartbeat_timer` (NULL callback) + `heartbeat_work`
  (never submitted) were non-functional dead code — the device never sent UDP
  keepalive frames. Removed entirely; keepalive is not needed (the client
  does not depend on device-originated heartbeats).

### Documentation

- Product name unified: **ReSpeaker → reSpeaker** (lowercase `r`) across all
  docs, code comments, USB descriptors, and sample titles.
- README rewritten with hardware overview, full build/flash guide, and links
  to official Nordic (NCS, nRF5340, nRF7002, NPM1300) + Zephyr docs.
- Console baud rate corrected: 115200 → 921600 (the board overlay sets
  uart0 to 921600).
- WiFi password note: `12345678` is the default; becomes random after the
  first BLE pairing (`config_generate_wifi_password`).
- NCS version in skills corrected: v3.2.1 → v3.3.0.

## Upgrading

### 1. USB Serial DFU (recovery — last-resort, no programmer needed)

This is the **customer recovery path**: if a custom application breaks the
device, hold the user button while connecting USB to enter MCUboot serial
recovery, then reflash the factory firmware with `nrfutil`:

> **nrfutil docs**: <https://docs.nordicsemi.com/bundle/nrfutil/latest/page/guides/device_tools/mcu_manager_serial.html>

```sh
# Install the mcu-manager component (one-time)
nrfutil install mcu-manager

# Upload the signed image (use the .hex, not the .bin)
nrfutil mcu-manager serial image-upload \
    --firmware clip-0.0.7-production-signed.bin \
    --serial-port /dev/ttyACM0

# Reset to apply (MCUboot verifies the signature and swaps on next boot)
nrfutil mcu-manager serial reset --serial-port /dev/ttyACM0
```

> On Windows replace `/dev/ttyACM0` with `COM12` (or the actual COM port).

### 2. Programmer (J-Link / west)

```sh
west flash --build-dir build-clip && nrfutil device reset
```

## Build Environment

- NCS v3.3.0 (Zephyr RTOS), board `clip/nrf5340/cpuapp`
- `export ZEPHYR_EXTRA_MODULES=$(pwd)` before building (sysbuild: mcuboot + app + ipc_radio)
- 5 MCUboot patches applied by `scripts/build_release.sh`

## Known Issues

- Debug build idle current is higher than production due to the UART console
  leak (~570µA) — by design; use the production image for battery testing.
- The 4.25V charge termination is a mild overcharge of the 4.20V-rated cell;
  accepted to reach 100% at the cost of some cycle life.
- iOS Bluetooth list may accumulate orphaned "Clip XXXX" entries after
  multiple AT+PAIR=reset (identity rotation); cosmetic only.
